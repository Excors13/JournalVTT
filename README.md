# World Codex — Кодекс мира

**Версия 1.0.0 · Foundry VTT 14+ · интерфейс на русском.**

Книжная компоновка в духе BG3 с угольным фоном, светлым текстом и красными акцентами. Модуль не зависит от PF2e или другой игровой системы. В нём используются стандартные журналы Foundry, собственные метаданные в flags и локальные SVG-значки. Внешних серверов, платных библиотек и обязательных дополнительных модулей нет.

## Загрузить проект на GitHub и установить

1. Создай **публичный репозиторий**, например `world-codex`.
2. Распакуй архив проекта. Загрузи **содержимое папки `world-codex` в корень репозитория**. Там должны лежать `module.json`, `README.md`, `scripts/`, `styles/`, `assets/`, `tools/`, `tests/`, `package.json` и обязательно `.github/workflows/release.yml`. Не загружай один ZIP вместо исходников и не добавляй лишнюю папку `world-codex` внутри репозитория.
3. На GitHub открой **Actions → Publish Foundry release → Run workflow**. Версия — **`1.0.0`**. Если потребуется, включи Actions для репозитория.
4. Дождись зелёного результата. В **Releases → v1.0.0 → Assets** появятся **`module.json`** и **`world-codex.zip`**. Их создаёт сборщик; адреса твоего репозитория подставляются автоматически.
5. В Foundry открой **Add-on Modules → Install Module → Manifest URL** и вставь ссылку на `module.json` из Assets. Шаблон ссылки:

   ```text
   https://github.com/USER/REPO/releases/latest/download/module.json
   ```

   Замени `USER/REPO` на свой логин и имя репозитория. Для установки используй именно опубликованный манифест релиза: исходный `module.json` до сборки не содержит адресов скачивания.
6. В нужном мире включи **World Codex — Кодекс мира** через **Manage Modules**, затем перезагрузи мир.

Если GitHub запрещает публикацию Assets, проверь **Settings → Actions → General → Workflow permissions → Read and write permissions**. Workflow использует встроенный `GITHUB_TOKEN`; личный токен не нужен.

Вместо ручного запуска Actions можно опубликовать Release с тегом `v1.0.0`: опубликованный релиз также запускает сборку. Создание одного черновика Release её не запускает.

## Открыть кодекс

- Кнопка **Кодекс мира** в панели журналов Foundry.
- Клавиша **J**: открывает кодекс, повторное нажатие закрывает его. При вводе текста в чате, полях или редакторе J печатает букву. Клавишу можно переназначить в настройках управления; ранее назначенные пользователем сочетания сохраняются.
- **Configure Settings → World Codex → Открыть кодекс**.
- Через Script-макрос:

  ```js
  game.modules.get("world-codex").api.open();
  ```

При первом входе мастера создаются личные дневники игроков. Общие страницы не создаются автоматически. В пустом кодексе мастер может нажать **«Создать демонстрационные записи»**: появятся пример задания, описание мира, место и карта. Демонстрация содержит только вымышленные материалы.

## Журналы, папки и цели

Порядок вкладок: **Задания → Мир → Персонажи → Фракции → Места → Бестиарий → Карты**. Главной страницы нет.

- Мастер создаёт журналы и папки слева. Папки можно переименовывать и перемещать через кнопку редактирования рядом с названием. Вложенность ограничена штатным пределом папок Foundry.
- Журналы можно перетаскивать в папки, в корень раздела и выше/ниже других журналов. Перемещение между папками не меняет состояние задания.
- Узкий разделитель между списком журналов и страницей скрывает и показывает левую панель. После скрытия остаётся ручка со стрелкой.
- Текст редактируется штатным **ProseMirror** Foundry: заголовки, списки, форматирование, изображения и `@UUID[...]`.
- Справа находятся изображение и **«Основные сведения»** — произвольные пары названия и значения. Их можно добавлять, переименовывать, переставлять и удалять в редакторе. Длинный основной текст прокручивается отдельно от правой колонки.
- У задания есть общее состояние и список целей. Состояние каждой цели меняется в редакторе и прямо при чтении. Выполненная цель зелёная, проваленная — красная; состояние также обозначено значком.
- Отдельного списка «Связанные страницы» нет. Для ссылок используются возможности Foundry внутри текста.
- Кнопка открытия стандартного журнала Foundry видна только мастеру и помощнику мастера. У игроков её нет, даже при уровне «Владелец».

Создание/удаление общих записей и управление папками доступны мастеру. Игрок с уровнем «Владелец» может дополнять существующие записи, включая текст, сведения, изображение, цели и карту. Глобальные разрешения Foundry на просмотр файлов и загрузку изображений продолжают действовать.

## Навигация и чтение в 1.0

- **Кодекс на весь экран** в шапке разворачивает окно на рабочую область Foundry. Повторное нажатие возвращает прежнее положение и размер. Нативные диалоги и файловый менеджер остаются доступны. Режим сохраняется при закрытии и открытии кодекса в текущем сеансе.
- Кнопки **Назад / Вперёд** возвращают к просмотренным разделам, записям и страницам дневников. Недоступные и удалённые записи пропускаются. История локальна для открытого сеанса.
- **Поиск по кодексу** слева ищет по доступным названиям, текстовым страницам, сведениям и целям во всех разделах. Личные дневники не включаются в общий поиск. Секретные текстовые блоки учитываются только для пользователей, которым они доступны. При ограниченном доступе поиск учитывает только название.
- **A− / A+** меняют основной текст в пределах 12–22 px. Выбор сохраняется отдельно на клиенте; доступен также в настройках Foundry.
- В шапке нет имени пользователя; переключатель бокового меню расположен на разделителе.

## Журналы в стандартной панели Foundry

Для игроков и доверенных игроков записи и папки кодекса, включая личные дневники, скрываются из стандартного каталога журналов Foundry. Владение записью не отменяет это правило. В кодексе доступ к чтению и редактированию остаётся прежним. Мастеру и помощнику мастера стандартный каталог доступен.

Это организация интерфейса, а не дополнительный уровень секретности: права документов продолжает проверять Foundry. Материалы, которые игрок не должен знать, должны иметь соответствующие права доступа.

## Добавить существующий журнал

Мастер нажимает кнопку импорта рядом с **Журнал / Папка**, выбирает обычный журнал мира и раздел. Исходный документ перемещается в папку кодекса с сохранением UUID, всех страниц, текста, изображений и текущего владения. Права становятся индивидуальным исключением. Для перехода на общие права можно нажать **Права раздела**. Компендий сначала нужно импортировать в мир штатными средствами Foundry.

Если у добавленного журнала несколько текстовых страниц, над содержимым появляются кнопки страниц. Редактирование меняет только выбранную страницу. Изображения и другие типы страниц сохраняются в документе и доступны мастеру в штатном журнале.

## Уведомления заданий

При переходе существующей цели в **Выполнена** или задания в **Завершено** у пользователей с доступом к чтению появляется небольшое окно **«Задание дополнено»** в левом нижнем углу. Кодекс может быть закрыт. Уведомление исчезает через пять секунд и закрывается вручную. Повторные обновления одного задания объединяются; одновременно показывается до трёх окон.

Переименование, редактирование текста, провал цели и обычная загрузка мира уведомлений не вызывают. Пользователи без доступа к заданию их не получают; офлайн-события при входе не воспроизводятся.

## Карты

1. Создай журнал в разделе **«Карты»**, задай название и выбери изображение через стандартный файловый менеджер Foundry. Можно указать существующий путь или HTTP(S)-адрес. Файл должен быть доступен всем участникам, которым открыта карта.
2. Перемещай карту перетаскиванием фона, меняй масштаб колесом или кнопками внизу. Есть вписывание карты и полноэкранный просмотр.
3. Нажми **«Редактировать карту» → «Добавить метку»**, затем укажи точку. Задай название, значок и журнал. Поле UUID принимает ссылку на журнал или текстовую страницу; в него можно перетащить журнал из стандартной панели Foundry.
4. Доступны 11 значков без подложки: деревня, крепость, город, столица, книга/интересное место, вопрос, военный лагерь, гробница, пещера, гнездо чудовищ и руины города.
5. В режиме редактирования метки перетаскиваются. Нажатие открывает их редактор с возможностью удаления. В режиме просмотра открывается мини-окно с основным текстом доступного журнала и целями, если это задание. Изображение и правые сведения в мини-окно не дублируются.
6. **«Открыть журнал»** переводит к полной записи; **«К карте»** возвращает к сохранённому положению и масштабу. Если привязан обычный журнал вне кодекса, он открывается в стандартном окне Foundry.
7. **«Добавить подпись»** размещает отдельный текст на карте. Все подписи используют Georgia. Есть обычное/жирное начертание, курсив, размер 12–64 px, выравнивание, цвет, поворот и обводка. В режиме редактирования подписи перемещаются и открываются нажатием для изменения или удаления.

В редакторе метки или подписи мастер может включить **Скрыть от игроков**. Скрытый элемент виден мастеру полупрозрачным, игрокам не рисуется, в том числе владельцам карты. Снятие флажка раскрывает элемент. При сохранении карты игроком скрытые элементы сохраняются. Это скрытие в интерфейсе карты; для секретного содержимого связанного журнала нужны отдельные права.

Метки и подписи хранятся в данных карты и сохраняются после перезапуска. Координаты привязаны к изображению, а не к размеру окна. Масштаб и смещение сохраняются в открытом окне кодекса при переходах между записями. Если заменить изображение карты, элементы сохранят нормализованные позиции; их можно переставить под новую картинку.

## Права по ролям Foundry

Открой **«Настройки»** внутри кодекса или **World Codex → Владение по умолчанию** в настройках Foundry. Для каждого раздела выбираются уровни **Нет доступа / Ограниченный / Наблюдатель / Владелец** отдельно для **Игрока** и **Доверенного игрока**.

По умолчанию обе роли читают общие разделы; **Доверенный игрок владеет разделом «Мир»**, а заданиями не владеет. Для изменения карты нужен уровень «Владелец» в разделе «Карты» либо индивидуальное владение конкретной картой. Уровень «Ограниченный» показывает название в оглавлении, но не открывает текст.

Права записываются в обычное поле ownership журнала и проверяются Foundry. Настройки раздела применяются к новым записям; флажок в настройках позволяет применить их и к существующим записям, которые наследуют права раздела. При изменении роли пользователя наследуемые права пересчитываются мастером. Мастер может нажать **ПКМ по названию журнала в списке кодекса**: откроется штатное окно Foundry со списком игроков и индивидуальными уровнями владения. Это же окно доступно через кнопку **«Доступ»** над открытой записью. Если изменить владение конкретным журналом через ПКМ или **«Доступ»**, это становится ручным исключением: общая синхронизация не затрёт его. Кнопка **«Права раздела»** возвращает наследование.

Под названием журнала мастер видит число игроков с доступом к чтению и режим прав — раздел или индивидуальные. Подсказка перечисляет уровни каждого игрока.

Мастер и помощник мастера сохраняют штатные привилегии Foundry. Таблица не изменяет посторонние журналы мира.

## Личные дневники

Иконка книги слева от вкладок открывает личные дневники. Игрок видит свой дневник, добавляет записи и редактирует их штатным текстовым редактором. Мастер видит дневники всех игроков и читает записи из того же интерфейса; редактирование чужого дневника в кодексе не предлагается.

Другие игроки доступа не получают. Правила общих разделов не распространяются на дневники. Для создания журнала требуется хотя бы один вход полного мастера с включённым модулем; дальше игрок может писать и без мастера онлайн. Кнопка **«Проверить личные дневники»** в настройках создаёт недостающие дневники.

## Данные, обновления и проверка

Записи — обычные `JournalEntry`, текст — `JournalEntryPage`; метаданные, сведения, цели и карты — `flags.world-codex.data`. Папки — штатные папки Foundry. Всё попадает в резервную копию мира. После отключения модуля текст остаётся доступен в обычных журналах; специальный интерфейс карт и сведений требует модуля.

При обновлении с 0.1.0 существующий текст сохраняется, прежние пути папок преобразуются в штатные папки. Старые флаги связей остаются для восстановления, но не показываются отдельным блоком. Произвольные сторонние журналы не преобразуются автоматически; их можно привязать к меткам карты.

Если запись изменилась с момента открытия редактора, сохранение устаревшей версии блокируется. Скопируй свой текст и открой запись заново. Совместного редактирования одного текста в реальном времени нет; основной текст и метаданные сохраняются отдельными стандартными операциями Foundry.

**Перед выпуском выполнены автоматические тесты хранения, прав, карт и сборки, а также браузерная проверка интерфейса с имитацией API. Настоящий лицензированный сервер Foundry и конкретная сборка PF2e здесь не запускались.** В манифесте указана целевая совместимость с веткой Foundry 14 (`minimum: 14`, `verified: 14`); верхнего запрета установки нет. Более новые поколения не отмечены как проверенные. Проверка реального редактора, окон Foundry и совместимости с другими модулями выполняется в игровом мире.

## Для следующих версий

Обнови `version` в `module.json` и `package.json`, затем запусти тот же Workflow с новым номером, например `1.0.1`. Постоянная ссылка на `releases/latest/download/module.json` остаётся прежней.

Проверки без установки зависимостей:

```sh
npm test
python3 -m unittest discover -s tests -p 'test_*.py'
```

Локальная сборка:

```sh
python3 tools/build_release.py --repo USER/REPO --version 1.0.0
```

В `dist/` появятся манифест и устанавливаемый ZIP. Для локальной ручной установки можно собрать без `--repo` и распаковать `dist/world-codex.zip` в `Data/modules/world-codex`, чтобы `module.json` лежал прямо внутри этой папки.

Если сообщаешь об ошибке, укажи версию Foundry, игровую систему, роль пользователя, действие перед ошибкой и красный текст из консоли F12. Содержимое дневников присылать не нужно.
